# Reference solution — Notebook 10

## What the exercise is testing

Extend the commerce model to represent payments correctly.

## Reference approach

Payments should normally be modeled at payment-event grain: one row per payment attempt/transaction, with a stable payment key and an order foreign key. Multiple payments per order should be representable without overwriting history; settlement status belongs to the payment event.
